# DK-DOCS-BUG-20261115-schema-model-source-description: the report schema says model.source comes from the model name alone

**Date Discovered:** 2026-11-15
**Severity:** LOW
**Status:** OPEN
**Label:** [ticket]
**Found by:** the model-source task agent, read in code
**Filed by:** the model-source task agent

## Problem
A user reading `schema/report.v1.json` (line 270) for `manifest.model.source` sees "Source is
the host the weights download from, derived from Ref by manifest.ModelSource; omitted when Ref
is a local path or unknown." Since the model-source fix, `ModelSource` also reads the env
allowlist: a mirror (`HF_ENDPOINT`, `MODEL_ENDPOINT`) gives the mirror's host, ModelScope gives
`modelscope.cn`, and offline mode omits the field even for a Hub id.

Cause: the description is generated by `make schema` from the doc comment on
`ManifestModel.Source` in `internal/model/report.go:104-106`. Changing the comment changes the
generated schema, which the model-source task kept off-limits.

## Why it matters
CI jobs consuming the JSON report read the schema to know what a field means. The text is not
false for a pod with no such variables, but it under-states when the field is omitted and
where a non-Hub host comes from.

## Options
1. Edit the comment to "derived from Ref and the env allowlist by manifest.ModelSource; omitted
   when nothing is known to be downloaded (a local path, offline mode)" and run `make schema`.
   Recommended: one comment, one regenerated file, no field change (append-only holds).
2. Leave it; the README states the behaviour.
